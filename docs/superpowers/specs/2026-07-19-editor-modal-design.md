# 工具编辑界面改为 Modal 弹窗

## 背景

当前「编辑工具」表单渲染在右侧帮助面板内（`helpWidth` 默认 340px，最大 560px）。随着字段增多（名称、图标、分组、cwd、工具根目录、tmux、启动命令、本地 Markdown、远程订阅等），窄边栏里表单堆叠、Markdown 编辑区局促，编辑体验下降。

## 目标

在不改变任何表单功能、数据模型、IPC 或后端行为的前提下，把工具编辑界面从右侧窄边栏迁到一个独立的 Modal 弹窗中，让编辑者获得更宽敞、聚焦的编辑空间。

## 方案选择

| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| A. 右侧分 Tab | 把现有右侧表单拆成多个 Tab | 终端始终可见；改动小 | Markdown 仍受限；频繁切 Tab |
| B. **Modal 弹窗**（选中） | 点击「编辑」后弹出居中 Modal | 空间最大；Markdown 书写最舒服；字段布局最舒展 | 编辑时暂时看不到终端 |
| C. 现有结构内优化 | 加宽右侧面板、优化间距分组 | 改动最小 | 宽度天花板仍在，无法根本解决 |

选中方案 **B**，因为本次优化优先级是**编辑体验**，Modal 能彻底解决窄面板问题。

## 设计细节

### 容器

- 新增组件 `EditorModal`（可放在 `src/renderer/components/EditorModal.tsx`）。
- 复用现有 `.modal-overlay` / `.modal` 视觉体系，但单独定义一个更宽的变体（例如 `.editor-modal`）。
- 尺寸：默认宽度 `720px`，`max-width: 90vw`；`max-height: 90vh`；主体可滚动。
- 位置：屏幕居中，背景半透明蒙层。

### 触发与关闭

- 触发：在 `App.tsx` 中，当 `editingId` 不为空时渲染 `EditorModal`；**不再**把 `EditorPane` 嵌在右侧帮助区。
- 关闭方式：点击遮罩层、点右上角 ×、按 `Esc`、点「取消」、或保存成功后自动关闭。
- 快捷键：`Cmd/Ctrl + Enter` 触发保存。

### 内部布局

`EditorModal` 的内容沿用 `EditorPane` 的字段和状态逻辑，但重新排布：

1. **Header**：标题「编辑工具」+ 当前工具名称，右侧关闭按钮。
2. **Body（可滚动）**：
   - **基本**：双列网格——名称 / 图标；分组 /（必要时占满）。
   - **终端**：双列网格——起始目录 / 工具根目录；tmux 会话名 / 自动更新间隔。
   - **启动命令**：全宽 textarea，3–4 行。
   - **内容来源**：沿用「本地内容 / 远程订阅」Tab；Markdown 编辑区和远程预览区获得更宽横向空间。
3. **Footer**：左侧「保存」主按钮，右侧「取消」；保存过程中禁用按钮并显示「保存中…」。

### 与三栏布局的关系

- Modal 弹出时，左侧工具列表、中间终端、右侧帮助面板仍然可见于背景。
- 右侧帮助面板在编辑时继续显示当前工具的文档，不再被编辑表单替换。
- 新建工具后仍自动进入编辑状态（Modal 弹出）。

## 不变范围

- 不改动 `ToolMeta` / `Tool` 类型、后端命令、IPC 通道、数据文件格式。
- 不改动 `EditorPane` 的字段校验、保存逻辑、本地/远程 Tab 行为。
- 不改动导入/导出、配置记录、更新检查等其它功能。

## 实现要点

- 把 `EditorPane` 的「表单内容」提取或重构成在 Modal 内使用的布局；保留其 state 与 `save()` 行为。
- 在 `App.tsx` 中把
  ```tsx
  {active && editingId === active.meta.id ? <EditorPane ... /> : <HelpPane ... />}
  ```
  改为始终渲染 `HelpPane`，并在外层条件渲染 `EditorModal`。
- 新增/调整 CSS 类，确保 Modal 宽度、双列网格、滚动行为符合设计。
- 在 `EditorModal` 里监听 `keydown`，实现 `Esc` 关闭和 `Cmd/Ctrl+Enter` 保存。

## 验收标准

1. 点击工具「编辑」按钮后，弹出独立的 Modal 编辑弹窗，不再替换右侧帮助面板。
2. Modal 内字段清晰、间距舒适，Markdown 编辑区横向空间明显大于旧版右侧面板。
3. 保存、取消、关闭、快捷键行为符合预期，且功能与旧版一致。
4. 类型检查（`npm run typecheck`）和测试（`npm run test`、`cargo test`）保持通过。

## 后续可探索（不在本范围）

- 编辑时是否需要「分屏」保留终端可见（非 Modal）的替代模式。
- 是否需要 dirty 状态提示，防止误关闭导致未保存内容丢失。
